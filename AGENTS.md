# AGENTS.md

Instructions for AI coding agents working in this repository. Claude Code reads it to know which checks to run; Codex reads it before every review.

## Roles

Claude Code implements. Codex reviews read-only. The user decides and commits.

## Project

Loadstate is a fake REST API and scenario toolkit for front-end development and testing. The plan and contracts live in `docs/`: start with `docs/PROJECT-PLAN.md`, then `docs/API-SPEC.md` and `docs/TECHNICAL-DECISIONS.md`. Current milestone: M1a.

| Path | Contents |
|---|---|
| `packages/core` | Zod contracts (`src/contracts.ts`), the resource registry with each resource's relations and query rules (`src/resources.ts`), the generated fixture packs `core@1` and `edge@1` (`src/fixtures/`), the simulation controls and recipes (`src/controls.ts`), the SVG images and avatars (`src/images.ts`), the query parser (`src/query.ts`) and list pipeline (`src/list.ts`: search, filters, sort, pagination, cursors, links), write rules (`src/writes.ts`), Problem Details, the engine (`createEngine`) that routes and answers every `/v1` request, and the OpenAPI generator (`createOpenApiDocument`). Portable: no Node, DOM or Workers APIs. Its fixture generator lives in `scripts/` and runs only at development time. |
| `packages/server` | Hono adapter (`createApp`): health routes, the request body limit, and catch-alls that hand `/v1/*` and `/img/*` to an engine. Node entry (`node.ts`, executable `main.ts`) and Workers entry (`worker.ts`). |
| `packages/msw` | MSW 3 adapter (`createHandlers`) that forwards requests under a base URL to an engine. Portable: builds without Node types. |

Toolchain: Node `>=22.13.0` (24 is the reference), pnpm 12.11.2 through `packageManager`, TypeScript 6.0.3 with `strict`, Biome 2.5.15 for lint and format, Vitest 5. Use pnpm for every package command, including registry lookups.

Workspace packages resolve to their TypeScript sources through the `@loadstate/source` export condition: Vitest sets it in `vitest.config.ts`, typecheck configs set it through `customConditions`, and builds resolve to `dist`.

## Commands

The checks CI runs, in this order. `pnpm check` runs all four; `pnpm format` applies Biome fixes.

| Check | Command |
|---|---|
| Lint | `pnpm lint` |
| Typecheck | `pnpm typecheck` |
| Build | `pnpm build` |
| Test | `pnpm test` |

Lint, typecheck and test are read-only. Build writes `dist/` folders, which git ignores.

When `pnpm` cannot start, for example in an offline sandbox where Corepack cannot fetch the pinned pnpm, run the same read-only checks through Node from the repository root:

| Check | Command |
|---|---|
| Lint | `node node_modules/@biomejs/biome/bin/biome check .` |
| Typecheck | `node node_modules/typescript/bin/tsc -p packages/<name>/tsconfig.json` for `core`, `server` and `msw` |
| Test | `node node_modules/vitest/vitest.mjs run` |

Tests that start a server on `127.0.0.1` need loopback networking; report them as not run if the sandbox blocks it.

CI then runs two smoke checks. Both build first, write to a temporary directory or `dist/`, and start local servers, so a read-only reviewer reports them as not run.

| Check | Command | Proves |
|---|---|---|
| Pack | `pnpm smoke:pack` | Each tarball holds exactly `package.json`, `LICENSE` and the compiled `src` files; the packages install into a fresh project and work there with plain Node and TypeScript |
| Worker | `pnpm smoke:worker` | The Workers entry runs under local Wrangler and answers health, lists, a fixture avatar and a placeholder SVG, a projected cursor walk, an expanded read, a delayed header-driven 503, the edge pack, an HTML body fault, a stateless create, PATCH and DELETE, a blocked delete, 405 and 413 |

`pnpm --filter @loadstate/server dev:worker` runs the Workers entry locally for manual use.

The public demo runs on Cloudflare Workers at `https://loadstate.veliksergey.workers.dev`. It is deployed manually from a logged-in machine with `pnpm build` then `pnpm --filter @loadstate/server exec wrangler deploy`, only with the user's explicit authorization for that deploy. CI never deploys.

## Branches

`main` is the default branch of `github.com/veliksergey/loadstate`. CI runs on pushes and pull requests to `main`. Agents never commit, push, tag, publish or deploy without the user's explicit authorization for that action.

## Invariants

- `packages/core` stays portable. Its build config has no Node or DOM types, so a Node-only API in core fails `pnpm build`.
- Built-in fixtures are deterministic and immutable: `core@1` is generated by `packages/core/scripts/fixtures.ts` from a fixed seed and reference time, `edge@1` is written by hand in `packages/core/scripts/edge-fixtures.ts`; both are committed as `src/fixtures/*.generated.ts`, frozen at load, and never edited by hand. Change a generator and run `pnpm --filter @loadstate/core fixtures:generate`; `test/fixtures.test.ts` fails if a committed pack, its checksum or the Faker version drift, and runs every invariant on both packs.
- Image URLs are stored root-relative and made absolute per response from a trusted base URL, never a hard-coded host.
- `/img` SVGs come from fixed templates in `src/images.ts`: user text is XML-escaped and length-limited, and the output has no script, event handler, `foreignObject`, link or external reference. `test/images.test.ts` checks worst-case inputs; image responses also send `nosniff` and a `Content-Security-Policy` that forbids scripts and external loads.
- Simulation controls are parsed and resolved in core (`src/controls.ts`), so every adapter honors them identically. The engine never waits: a simulated delay is an effect (`delayMs`) that the Hono app and the MSW handlers carry out.
- Routing and behavior for `/v1` live in the core engine, so every adapter answers identically. Adapters translate requests and responses only; `packages/msw/test/parity.test.ts` proves the Node HTTP and MSW adapters match the in-process engine.
- The OpenAPI document is generated from the Zod contracts and never written by hand. `packages/core/test/openapi.test.ts` validates it against the official OpenAPI 3.1 and 3.2 meta-schemas and checks engine responses against it, so a new route, status or field needs a matching change in `packages/core/src/openapi.ts`.
- Each engine is an isolated run: records, next ids and sequence positions never leak between engines, and `reset()` restores all of them.
- Write rules live in `packages/core/src/writes.ts`: each resource's input contract, defaults, references, structural checks and derived fields. A stored record always satisfies its record schema and the pack's structure, and deletes never cascade.
- REST errors are RFC 9457 Problem Details (`application/problem+json`) with a stable `code`. A 5xx body never contains an exception message or stack.
- Query input is validated strictly. Invalid, out-of-range, repeated, conflicting and unknown parameters return 400; nothing is coerced or silently ignored. A filter's type comes from the record's Zod schema, and the OpenAPI parameters come from the same name lists the parser accepts (`listParameterNames`, `readParameterNames`).
- Cursors bind the route, the fixture pack, the search, the filters and the sort, and end their sort tuple with the unique `id`; links and image URLs use only the trusted base URL an adapter passes in: the configured `publicUrl` or the listening origin on Node, never the `Host` header.
- The Node server binds to loopback unless a caller explicitly passes another host.
- The public demo is stateless, simulation controls never bypass host limits, and management never shares the data routes (`docs/TECHNICAL-DECISIONS.md`, section 6).
- Package builds start from an empty `dist`, and a packed manifest points only at `dist` (`publishConfig.exports`).
- Dependency install scripts stay disabled unless reviewed: every package with one is listed in `allowBuilds` in `pnpm-workspace.yaml`, and pnpm fails the install for any that is not.
- Code comments are one short line explaining a non-obvious reason.
